## 1. نظرة عامة على النظام

### 1.1 المكوّنات

| المكوّن | التقنية | المكان |
|---|---|---|
| واجهة الأدمن | React + Vite + Tailwind | تُبنى إلى `admin/frontend/dist` وتُقدَّم من نفس السيرفر على `/admin` |
| الـ API | Node.js + Express | `admin/backend/server.js` |
| قاعدة البيانات | Turso (LibSQL / SQLite سحابي) | `libsql://everest-academy-ziad-assem648.aws-eu-west-1.turso.io` |
| الاستضافة | Railway (الباك إند + واجهة الأدمن) | `everest-academy-production.up.railway.app` |
| موقع المستخدم | Hostinger | `myeverestcompany.com` |
| الفيديوهات | Bunny.net | تُرفع من صفحة الكورسات |

### 1.2 كيف تتحرك البيانات

```
زر في صفحة الأدمن
   ↓
api.js  (يضيف هيدرز الجلسة + كاش GET)
   ↓  fetch
Express Route  (adminAuth / sessionAuth)
   ↓
db.js  (query / queryOne / execute)
   ↓
Turso
   ↓
الرد يعود → الصفحة تُحدَّث → الكاش يُمسح عند أي تعديل
```

### 1.3 المصادقة والصلاحيات

- تسجيل الدخول: `POST /api/admin-auth/login`.
- بعد الدخول يُحفظ في `localStorage.admin_session`:
  ```json
  { "userId": "admin-001", "token": "…", "user": { "full_name": "Admin", "role": "admin" } }
  ```
- كل طلب يحمل:
  - `x-user-id`
  - `x-session-token`
- **حد الجلسات:** أقصى جلستين نشطتين لكل أدمن. الجلسة الثالثة تُلغي الأقدم.
- **الأدوار:**
  - `admin` — كل الصفحات ما عدا «إدارة الأدمنز».
  - `manager` — كل الصفحات + «إدارة الأدمنز».
- كلمة المرور مُشفّرة بـ `bcrypt`.
- تسجيل الخروج يمسح الجلسة من السيرفر والكاش من المتصفح.

### 1.4 لماذا الأدمن سريع؟

ثلاث طبقات تعمل معاً:

1. **Keep-alive للصفحات:** الصفحة التي زرتها تبقى محمّلة ومخفية (`display:none`) بدل إعادة بنائها. الرجوع إليها فوري. إذا مرّ أكثر من دقيقتين بدون زيارتها تُعاد بناؤها لتحديث البيانات.
2. **كاش GET في `api.js`:**
   - بيانات «طازجة» لمدة **20 ثانية** → تُعرض فوراً بدون طلب.
   - بعد 20 ثانية تُعرض النسخة القديمة وتُحدَّث في الخلفية (stale-while-revalidate) حتى **5 دقائق**.
   - أي عملية كتابة (POST/PUT/DELETE) أو تسجيل خروج **يمسح الكاش** بالكامل.
3. **إزالة الصور Base64 من قائمة المستخدمين:** `GET /api/users` يُرجع البيانات بدون الصور لتقليل الحجم (القائمة ~220 KB بدل عدة ميجابايت). الصورة الكاملة تُجلب عند فتح الملف الشخصي فقط.

### 1.5 تحميل الأزرار والتأكيد

- **كل زر** يُظهر Overlay «جاري التنفيذ...» أثناء الطلب.
- **التأكيد يظهر فقط** للإجراءات الحساسة:
  حذف، مسح، إزالة، حظر، إيقاف، تعطيل، تحويل، سحب، خصم، رفض، استرداد، تصفير، إعادة تعيين.
- الأزرار التي عندها تأكيد خاص بها (مثل `confirm()` الأصلي أو نافذة تأكيد مخصّصة) تحمل `data-no-confirm` حتى لا يظهر تأكيد مزدوج.
- يوجد **لودر واحد فقط** في الشاشة: لودر الصفحة يُخفى تلقائياً أثناء عمل الـ Overlay.

## 2. تسجيل الدخول والشريط الجانبي والعناصر المشتركة

### 2.1 شاشة تسجيل الدخول

**المسار:** `/admin/`

| العنصر | الوظيفة |
|---|---|
| شعار Everest + العنوان | هوية اللوحة |
| حقل البريد | بريد الأدمن |
| حقل كلمة المرور | كلمة المرور |
| زر «دخول» | يرسل البيانات إلى `/api/admin-auth/login` |
| زر تبديل الوضع الليلي/النهاري | يحفظ التفضيل في المتصفح |
| رسالة الخطأ | تظهر أسفل النموذج عند بيانات خاطئة |

**ملاحظات:**
- البريد يُطبَّع (حروف صغيرة، إزالة المسافات) وكلمة المرور تُطبَّع قبل المقارنة.
- عند النجاح تُحفظ الجلسة وتُفتح صفحة الإحصائيات.
- عند فشل الجلسة لاحقاً (401) يعود المستخدم لشاشة الدخول.

### 2.2 الشريط الجانبي

- يحتوي **22 صفحة** (23 مع «إدارة الأدمنز» لمدير النظام).
- كل عنصر: أيقونة + اسم الصفحة.
- الصفحة الحالية مميّزة بخلفية بنفسجية.
- على الموبايل: زر ☰ يفتح الشريط، والضغط على أي صفحة يغلقه.
- زر تبديل الوضع الليلي داخل الشريط أيضاً.

### 2.3 الشريط العلوي

| العنصر | الوظيفة |
|---|---|
| شارة الدور | `🔧 Admin` أو `👑 Manager` |
| اسم المستخدم | اسم الأدمن الحالي |
| 🌙 / ☀️ | تبديل الوضع الليلي |
| English / العربية | تبديل لغة الواجهة فوراً (كل النصوص لها نسختان) |
| 🚪 خروج | إنهاء الجلسة ومسح الكاش |

### 2.4 نافذة التأكيد (ActionGuard)

تظهر عند الضغط على زر حساس:

```
⚠️ تأكيد الإجراء
هل أنت متأكد من حذف؟
[ إلغاء ]  [ نعم، متأكد ]
```

- إن كان الزر يملك تأكيداً خاصاً به، لا تظهر هذه النافذة (لتجنّب السؤال مرتين).
- النافذة تظهر **فوق** الـ Overlay.
- الـ Overlay لا يمنع التنقل أثناء القراءة، لكنه يقفل الشاشة أثناء الكتابة.

### 3.1 الإحصائيات (Dashboard)

**الهدف:** صورة سريعة عن المنصة، وكل رقم قابل للضغط لعرض تفاصيله.

**البيانات:** `GET /api/dashboard/stats`

#### ما تراه في الصفحة

**أ) 4 بطاقات رئيسية (قابلة للضغط):**

| البطاقة | المعنى | عند الضغط |
|---|---|---|
| 👥 إجمالي المستخدمين | كل الحسابات ما عدا الأدمنز والمديرين | قائمة كل المستخدمين |
| 🎓 الطلاب | الحسابات من نوع `student` | قائمة الطلاب |
| 📚 الكورسات | إجمالي الكورسات + عدد المنشور منها | قائمة الكورسات |
| ✅ الاشتراكات النشطة | الاشتراكات المقبولة / الإجمالي | الاشتراكات المقبولة |

**ب) 3 دوائر نسب (Ring Charts):**

| الدائرة | البسط / المقام |
|---|---|
| معدل الموافقة على الاشتراكات | المقبولة / كل الاشتراكات |
| معدل نجاح الاختبارات | المحاولات الناجحة / كل المحاولات |
| الكورسات المنشورة | المنشورة / كل الكورسات |

**ج) 4 بطاقات «بانتظار الإجراء»:**

| البطاقة | عند الضغط |
|---|---|
| ⏳ بانتظار التفعيل | المستخدمون بحالة `pending` |
| 🛒 اشتراكات بانتظار المراجعة | الاشتراكات بحالة `pending` |
| 💳 شحن معلق | طلبات شحن المحفظة المعلقة |
| ⬆️ طلبات ترقية | طلبات ترقية نوع الحساب المعلقة |

**د) 4 بطاقات تحليلية:**

| البطاقة | عند الضغط |
|---|---|
| 🚫 الحسابات المحظورة | المستخدمون `blocked` |
| 🆓 حسابات التسجيل المجاني | `role = registration` |
| 💎 العمولات المدفوعة | كل العمولات |
| 📋 اختبارات ناجحة | المحاولات بنتيجة `pass` |

**هـ) 3 عناصر ملخّص:**

- إجمالي الاشتراكات
- اشتراكات بانتظار المراجعة
- التقييمات

#### كيف يعمل drill-down

- الضغط على أي بطاقة يفتح جدولاً أسفلها بعنوان مناسب.
- الصفحة تجلب **القائمة الكاملة** ثم تُصفّيها في المتصفح (مثلاً: كل الكورسات ثم تُبقي `status = published`).
- الضغط مرة أخرى على نفس البطاقة يغلق الجدول.
- أثناء الجلب يظهر «جاري التحميل...» داخل الجدول فقط.

#### ملاحظات

- كل الأرقام تُحدَّث عند إعادة فتح الصفحة (بعد دقيقتين) أو عند مسح الكاش.
- البطاقات لا تعدّل شيئاً؛ هي للعرض فقط.

### 3.2 تفعيل الحسابات — التسجيل الخارجي

**الهدف:** مراجعة الحسابات التي سجّلت من موقع المستخدم (تسجيل خارجي) وتفعيلها أو رفضها.

**البيانات:** `GET /api/users/pending-registrations?source=external`

#### ما تراه

- عنوان الصفحة + عدّاد «X مستخدمين بانتظار التفعيل».
- جدول بالأعمدة:
  1. الاسم
  2. البريد
  3. رقم الهاتف
  4. المحافظة
  5. **أنشأه** — يظهر المُنشئ أو المُحيل كزر؛ الضغط عليه يفتح ملفه الشخصي.
  6. **البطاقة** — زر «عرض» يفتح صور البطاقة/الباسبور.
  7. تاريخ التسجيل
  8. أزرار الإجراء.

#### الأزرار

| الزر | ماذا يفعل | التأكيد |
|---|---|---|
| 🎓 Student | تفعيل الحساب كطالب | لا |
| 🆓 Reg Free | تفعيل الحساب كتسجيل مجاني | لا |
| ❌ رفض | يفتح نافذة سبب الرفض | نافذة مخصّصة |

#### كيف يعمل التفعيل

1. `PUT /api/users/:id/approve-registration` مع `{ account_type }`.
2. يتحقق أن المستخدم ما زال `pending`.
3. يحوّل:
   - `student` → `role = student`
   - `registration_free` → `role = registration`
4. يضبط `status = active`.
5. يحسب انتهاء العضوية = الآن + `membership_duration` يوم (القيمة من إعدادات العضوية).
6. يمنح عمولة الإحالة للراعي (إن وُجد ولم يكن `commission_exempt`).
7. يُرسل إشعاراً للمستخدم.
8. يسجّل الإجراء في سجل الأدمن.

#### كيف يعمل الرفض

1. `PUT /api/users/:id/reject-registration` مع `{ reason }`.
2. يتحقق أن الحساب `pending`.
3. يضبط `status = rejected` ويحفظ سبب الرفض.
4. يُرسل بريداً للمستخدم بسبب الرفض (إن كان البريد مضبوطاً).
5. يسجّل الإجراء.

#### نافذة البطاقة

- `GET /api/users/:id/id-cards`
- تعرض صورة البطاقة الأمامية (وغيرها إن وُجدت).
- تدعم الروابط النسبية والمطلقة و`data:`.

#### ملاحظات

- الرفض يتطلب كتابة سبب (الزر معطّل حتى تكتب).
- لا يمكن تفعيل حساب غير `pending` (يرجع 400).
- الصفحة لا تعرض إلا المصدر المحدد (`external`).

### 3.3 تفعيل الحسابات — إنشاء حساب لآخر

**الهدف:** نفس صفحة 3.2 لكن للحسابات التي أنشأها عضو آخر داخل المنصة.

**الفرق الوحيد:** `source=created`.

- عمود «أنشأه» يعرض المُنشئ بشارة بنفسجية.
- بقية الأعمدة والأزرار والسلوك مطابق تماماً.
- التفعيل هنا أيضاً يمنح عمولة الإحالة للمُنشئ/الراعي حسب منطق الـ MLM.

### 3.4 إدارة المستخدمين

**الهدف:** المركز الرئيسي للتحكم في أي مستخدم: بياناته، رتبته، رصيده، فريقه، وسجله.

**البيانات:** `GET /api/users` (بدون صور) + `GET /api/ranks`

#### أعلى الصفحة

| العنصر | الوظيفة |
|---|---|
| العنوان «👤 إدارة المستخدمين» | — |
| عدّاد المستخدمين | عدد النتائج بعد البحث |
| زر «🗑️ حذف المحدد (X)» | يظهر عند تحديد مستخدمين |
| حقل البحث | يبحث بالاسم أو البريد أو الهاتف أو ID فوراً |

#### جدول المستخدمين

| العمود | المحتوى |
|---|---|
| ☑️ | تحديد فردي |
| ☑️ (رأس الجدول) | تحديد الكل / إلغاء الكل |
| الاسم | الاسم + البريد + ID |
| الهاتف | رقم الهاتف |
| الدور | `student` / `registration` / `admin` |
| نوع الحساب | `student` / `registration_free` |
| الرتبة | اسم الرتبة الحالية |
| الرصيد | `e_money` |
| الحالة | نشط / قيد المراجعة / مرفوض / محظور |
| الإجراء | عرض / إرسال $ / حظر أو فك الحظر / حذف |

#### إجراءات الجدول

| الزر | ماذا يفعل |
|---|---|
| عرض | يفتح الملف الشخصي الكامل (6 تبويبات) |
| 💰 إرسال $ | نافذة مبلغ → `PUT /api/users/:id/e-money` بـ `allow_negative:false` |
| حظر | `PUT /api/users/:id/block` — يمنع الدخول للمنصة |
| فك الحظر | `PUT /api/users/:id/unblock` |
| حذف | نافذة تأكيد مخصّصة → `DELETE /api/users/:id` |

#### حذف المحدد

- يظهر فقط عند تحديد مستخدم واحد أو أكثر.
- يسأل `confirm()` بعدد المستخدمين.
- يحذف كل مستخدم على حدة (لو فشل واحد يكمل الباقي).
- لا يمكن التراجع.

#### الملف الشخصي (النافذة الكبيرة)

**الرأس:**

- الاسم + شارة «محظور» إن كان محظوراً.
- **👤 دخول كـ هذا المستخدم** — `POST /api/users/:id/impersonate` ثم يفتح موقع المستخدم بجلسة مؤقتة (للتجربة والدعم).
- **✏️ تعديل** — يحوّل النافذة لوضع التحرير.
- ✕ إغلاق.

**وضع التحرير:**

| الحقل | ملاحظة |
|---|---|
| الاسم | — |
| البريد | — |
| الهاتف | — |
| العنوان | — |
| الدور | `registration` أو `student` |
| نوع الحساب | `student` أو `registration_free` |
| البايو | نص حر |

- «حفظ التعديلات» → `PUT /api/users/:id` ثم `PUT /api/users/:id/account-type` إن تغيّر النوع.

**التبويبات الستة:**

**1) 👤 البيانات:**

- بطاقات: المعرف، البريد، الهاتف، العنوان، الدولة.
- كود الإحالة، الرتبة الحالية (بأيقونة أو صورة الرتبة)، مبيعات الفريق، رصيد $.
- **👤 تم التسجيل من خلال:** الراعي؛ الضغط عليه يفتح ملفه.
- نوع الحساب + زر تحويل فوري للنوع الآخر.
- **🏅 تغيير الرتبة** (انظر أدناه).
- **💰 إضافة / خصم رصيد:** حقل رقم (موجب أو سالب) + تنفيذ → `PUT /api/users/:id/e-money` بـ `allow_negative:true`.
- **🔑 تغيير كلمة المرور:** 4 أحرف على الأقل.
- أزرار: حظر/فك حظر، السماح بالسالب، إيقاف/تفعيل العمولة، حذف المستخدم.
- **🏆 الرتب المحققة:** شارات الرتب التي أخذ عليها بونص.
- **👥 فريق التسويق:** تبويبات لكل مستوى (Level 1, 2, …) مع جدول (اسم، بريد، ID، رتبة، دور) وعدد كل مستوى.

**2) 📈 النشاط الأسبوعي:**

- إجمالي المبيعات المباشرة.
- مبيعات الطلاب.
- مبيعات التسجيل المجاني.
- المبيعات المؤهلة (أخضر إن حقق الحد الأدنى، أحمر إن لا).
- قائمة الأعضاء المباشرين (الاسم، النوع، الرصيد، الحالة، تاريخ التسجيل).
- ملخص الأهلية: الرتبة، الأعضاء المؤهلون، نسبة التقدم للرتبة التالية، تحقق الحد الأدنى.

**3) 🌐 الشبكة المؤهلة:**

- أعضاء الفريق المؤهلون.
- أعضاء طلاب / تسجيل مجاني.
- قائمة المباشرين مع وسم: ✅ مؤهل، ❌ غير نشط، ⚠️ رتبة أعلى من رتبتك (لا تُحتسب).

**4) 📜 السجل الأسبوعي:**

- أسابيع النشاط مع التفاصيل عند الضغط.

**5) 🏆 لوحة المتصدرين:**

- ترتيب أفضل الأعضاء حسب الأداء.

**6) 📊 سجل التسوية الأسبوعية:**

- قائمة أسابيع فيها أعضاء مباشرون.
- عند اختيار أسبوع: عدد الطلاب، عدد التسجيل المجاني، الإجمالي، وقائمة الأعضاء المباشرين في هذا الأسبوع.

#### تغيير الرتبة (أهم جزء)

1. تختار الرتبة الجديدة من القائمة (تعرض الرتبة + مبلغها).
2. تضغط «تغيير الرتبة».
3. إذا كانت نفس الرتبة → لا يحدث شيء.
4. إذا كانت **ترقية** تظهر نافذة:
   > 🎉 ترقية الرتبة
   > سيتم تغيير رتبة **الاسم** من **القديمة** إلى **الجديدة**
   > **هل تريد صرف كوميشن الرتبة (X $) له؟**
   - زر «نعم، اصرف الكوميشن»
   - زر «تغيير الرتبة بدون صرف»
   - زر «إلغاء»
5. إذا كانت **تخفيض** تظهر نافذة:
   > ⬇️ تخفيض الرتبة
   > **هل تريد خصم مبلغ رتبة القديمة (X $) من رصيده؟**
   - ملاحظة: الرصيد لا ينزل تحت صفر — يُخصم المتاح فقط.
   - زر «نعم، اخصم المبلغ»
   - زر «تغيير الرتبة بدون خصم»
   - زر «إلغاء»
6. التنفيذ: `PUT /api/users/:id/rank` مع:
   ```json
   { "rank": "Executive", "apply_bonus": "pay" }
   ```
   القيم الممكنة: `pay` / `deduct` / `none`.
7. الرد يحمل `unchanged` إن كانت نفس الرتبة، أو `bonus_applied` بالمبلغ المصروف/المخصوم.
8. تُسجَّل حركة في المعاملات وسجل النشاط، ويُرسل إشعار للمستخدم.

#### ملاحظات

- البحث يعمل على القائمة المحمّلة كاملة (client-side) لذا فوري.
- الصور لا تُحمَّل في القائمة؛ تظهر فقط داخل الملف الشخصي.
- «إيقاف العمولة» يضبط `commission_exempt = 1`: لا عمولات أسبوعية، لكنه يبقى مؤهلاً للترقية.
- حذف المستخدم يحذف بياناته المرتبطة (اشتراكات، معاملات، إشعارات…) حسب قيود قاعدة البيانات.

### 3.5 إدارة الصلاحيات

**الهدف:** تحويل نوع الحساب بين طالب وتسجيل مجاني بسرعة، ومراجعة الحسابات المعلّقة.

**البيانات:** `GET /api/users` ثم تصفية في المتصفح.

#### ما تراه

- عمودان:
  1. 🎓 **طالب (Student)** — `account_type = student` و`status = active`.
  2. 🆓 **تسجيل مجاني (Reg Free)** — `account_type = registration_free` و`status = active`.
- كل عمود به عدّاد وبحث خاص.
- قسم ثالث أسفل الصفحة: **⏳ في انتظار الموافقة** (كل `pending` غير الأدمنز).

#### بطاقة المستخدم داخل العمود

- الحرف الأول من الاسم (أخضر للطالب، بنفسجي للتسجيل المجاني).
- الاسم + البريد.
- زر 👁️ لعرض الملف.
- زر «→ 🎓 Student» أو «→ 🆓 Reg Free» لنقل الحساب للعمود الآخر.

#### كيف يعمل النقل

- `PUT /api/users/:id/account-type` مع `{ account_type }`.
- يغيّر النوع والدور المرتبط.
- يعيد تحميل القوائم.
- الصفحة تُحدّث نفسها تلقائياً عند الرجوع لتبويب المتصفح (visibilitychange).

#### ملاحظات

- هذا ليس تغيير رتبة؛ هو تغيير نوع الحساب فقط.
- المستخدمون المعلّقون يظهرون في القسم السفلي مع أزرار النقل أيضاً.

### 3.8 بناء الكورس

**الهدف:** إنشاء كورس جديد ببياناته الأساسية (بدون المواضيع والدروس — تُضاف من «قائمة الكورسات»).

**البيانات:** `GET /api/categories` + `POST /api/courses`

#### الحقول

| الحقل | إلزامي | ملاحظة |
|---|---|---|
| عنوان الكورس (عربي/إنجليزي) | ✅ | تبويب لغة للكتابة |
| وصف الكورس (عربي/إنجليزي) | ✅ | نص طويل |
| مستوى الصعوبة | — | مبتدئ / متوسط / متقدم |
| صورة الغلاف | ✅ | رفع صورة → `POST /api/upload` |
| السعر ($) | ✅ | 0 مرفوض |
| التصنيف | ✅ | قائمة + إضافة تصنيف جديد |
| الوسوم | — | مفصولة بفاصلة، تظهر كشارات |

#### الأزرار

| الزر | ماذا يفعل |
|---|---|
| العربية / English | تبديل لغة حقول العنوان والوصف |
| ✕ على الصورة | إزالة الصورة |
| اضغط لرفع الصورة | رفع صورة الغلاف |
| ＋ إضافة (بجانب التصنيف) | فتح نموذج تصنيف جديد |
| حفظ التصنيف | `POST /api/categories` ثم إضافته للقائمة واختياره |
| 🗑 حذف هذا التصنيف | `DELETE /api/categories/:id` (بتأكيد) |
| إنشاء الكورس | التحقق ثم `POST /api/courses` |

#### التحقق قبل الحفظ

- عنوان عربي أو إنجليزي موجود.
- وصف عربي أو إنجليزي موجود.
- صورة غلاف موجودة.
- سعر أكبر من صفر.
- تصنيف عربي مختار.
- أي حقل ناقص يُحدَّد بإطار أحمر + تنبيه.

#### بعد الحفظ

- تظهر شاشة نجاح: «تم إنشاء الكورس بنجاح!».
- زر «إنشاء كورس آخر» يعيد النموذج فارغاً.
- رسالة إرشاد للانتقال إلى «قائمة الكورسات» لإضافة المواضيع والدروس والاختبارات.

#### ملاحظات

- كل الكورسات مدفوعة؛ الدروس المجانية تكون «Preview» فقط.
- التصنيفات مشتركة مع صفحة قائمة الكورسات.

### 3.9 قائمة الكورسات

**الهدف:** إدارة الكورسات الموجودة: عرض، تعديل، منهج، طلاب، حذف.

**البيانات:** `GET /api/courses` + `GET /api/categories`

#### أعلى الصفحة

- العنوان + زر تحديث.
- بحث بالاسم.
- فلتر بالتصنيف.

#### الجدول

| العمود | المحتوى |
|---|---|
| صورة | الغلاف |
| العنوان | العنوان + عدد المواضيع/الدروس/الاختبارات + العنوان الآخر |
| التصنيف | عربي أو إنجليزي |
| السعر | `مجاني` أو `X $` |
| المؤلف | اسم المؤلف |
| الحالة | قائمة منسدلة: **منشور / مسودة** — التغيير يُحفظ فوراً `PUT /api/courses/:id` |
| إجراءات | عرض / تعديل / الطلاب / حذف |

#### زر «عرض»

يفتح مشغّل الكورس:

- يعرض الكورس كاملاً كما يراه الطالب.
- قائمة المواضيع والدروس.
- تشغيل فيديو الدرس.
- الدروس المجانية (Preview) متاحة.

#### زر «تعديل»

نافذة كبيرة بتبويبين:

**أ) معلومات الكورس:**

- العنوان والوصف (عربي/إنجليزي).
- السعر، السعر بالجنيه إن وُجد.
- الصورة، التصنيف (مع إضافة/حذف)، الوسوم.
- الصعوبة، الحالة.
- الحفظ → `PUT /api/courses/:id`.

**ب) المنهج:**

- **المواضيع:** إضافة موضوع، تعديل، حذف.
- **الدروس داخل كل موضوع:**
  - عنوان إنجليزي/عربي.
  - محتوى إنجليزي/عربي.
  - رابط فيديو YouTube **أو** رفع فيديو إلى Bunny (مع نسبة تقدم).
  - خيار «مجاني (Preview)».
  - حفظ / إلغاء / حذف.
- **الاختبارات داخل كل موضوع:**
  - إنشاء اختبار: نوع MCQ أو T/F أو مختلط.
  - إضافة أسئلة، خيارات (حتى 6)، تحديد الإجابة الصحيحة.
  - درجة النجاح.
  - تعديل/حذف.
- **الاختبار النهائي للكورس:** إضافة أو تعديل اختبار نهائي واحد.

#### زر «الطلاب»

- يفتح لوحة أسفل الصف.
- `GET /api/courses/:id/enrollments` (قائمة الطلاب).
- لكل طالب:
  - الاسم، البريد.
  - تعديل: الحالة (`pending` / `approved` / `rejected`) وتاريخ الانتهاء.
  - حفظ / إلغاء.
  - حذف الاشتراك (بتأكيد).

#### زر «حذف»

- `DELETE /api/courses/:id`.
- يحذف الكورس ومواضيعه ودروسه واختباراته واشتراكاته (حسب قيود القاعدة).

#### ملاحظات

- رفع الفيديو يدعم الاستكمال: لو انقطع الرفع، أعد المحاولة بنفس الملف.
- تغيير نوع الاختبار مع وجود أسئلة يسأل قبل حذفها.
- الحالة الافتراضية للكورس الجديد: `published` من صفحة البناء.

### 3.10 ظهور الكورسات

**الهدف:** التحكم في أماكن ظهور كل كورس منشور في موقع المستخدم.

**البيانات:** `GET /api/courses` (يُصفّى للمنشور فقط)

#### ما تراه

- عدّادات: 🆓 عدد الظاهر في المجانيات، 🏠 عدد الظاهر في الهوم، 📚 عدد الظاهر في صفحة الكورسات، وإجمالي المنشور.
- بحث.
- صف لكل كورس: الصورة، العنوان، التصنيف، السعر، وثلاثة مفاتيح:

| المفتاح | يتحكم في | الـ API |
|---|---|---|
| 🆓 صفحة المجانيات | `is_show_free` | `PUT /api/courses/:id/show-free` |
| 🏠 الهوم بيج | `is_show_homepage` | `PUT /api/courses/:id/show-homepage` |
| 📚 صفحة الكورسات | `is_show_courses` | `PUT /api/courses/:id/show-courses` |

#### كيف يعمل المفتاح

- الضغط عليه يقلب القيمة (0 ↔ 1) ويحدّث الواجهة فوراً.
- يُحفظ في القاعدة مباشرة.
- الهوم وصفحة الكورسات: **مفعّل افتراضياً** (يظهر ما لم تُضبط القيمة 0).
- المجانيات: **معطّل افتراضياً**.

#### ملاحظات

- لا تظهر الكورسات غير المنشورة هنا.
- تعطيل المفتاح لا يحذف الكورس، فقط يخفيه من ذلك المكان.

### 3.11 نتائج الاختبارات

  5. إجابات صحيحة (أخضر)

  8. النتيجة (ناجح/راسب)

#### ملاحظات

- «حذف الكل» لا يمكن التراجع عنه.
- المحاولات مرتبطة بالطالب والكورس والاختبار.

### 3.12 إدارة الرتب

**الهدف:** تعريف سلّم الرتب والمبالغ المترتبة عليها.

**البيانات:** `GET /api/ranks?all=true` (يشمل المعطّلة)

#### ما تراه

- 4 عدّادات: إجمالي الرتب، النشطة، المعطّلة، أعلى مكافأة.
- بطاقة لكل رتبة:
  - صورة/أيقونة الرتبة.
  - الاسم.
  - المكافأة (`bonus`) بالدولار.
  - المبيعات المطلوبة (`sales_required`).
  - شارة نشط/معطّل.
  - أزرار: تعطيل/تفعيل، تعديل، حذف.

#### إضافة/تعديل رتبة

| الحقل | المعنى |
|---|---|
| الاسم | اسم الرتبة (فريد) |
| المبيعات المطلوبة | حد المبيعات للوصول |
| المكافأة ($) | بونص الترقية |
| الصورة | رفع صورة (Base64) أو حذفها |
| نشط | يظهر للمستخدمين أم لا |

- الحفظ: `POST /api/ranks` أو `PUT /api/ranks/:id`.

#### الأزرار

| الزر | ماذا يفعل |
|---|---|
| + إضافة رتبة | فتح نموذج فارغ |
| تعطيل/تفعيل | `PUT /api/ranks/:id` بـ `is_active` |
| تعديل | فتح النموذج بالقيم الحالية |
| حذف | `DELETE /api/ranks/:id` (بتأكيد) |

#### ملاحظات

- الرتب النشطة فقط تظهر للمستخدمين.
- حذف رتبة مستخدمة قد يؤثر على عرض رتبة المستخدم؛ يُفضّل التعطيل بدل الحذف.
- قيم البونص الحالية:
  Star 0، Executive 2500، Executive Star 5500، Team Leader 8000، Senior Leader 12000، Regional Leader 18000، Everest Elite 25000، Everest Master 40000، Everest Legend 75000، Everest Ambassador 150000.

### 3.13 التسوية الأسبوعية

#### أ) 4 بطاقات حالة

| البطاقة | المعنى |

#### ب) إعدادات موعد التسوية

| الحقل | المعنى |
|---|---|
| تفعيل التسوية التلقائية | 🟢 مفعلة / 🔴 معطلة |

- **💾 حفظ الإعدادات** → 6 طلبات `PUT /api/settings/<key>`.
- **▶️ تشغيل التسوية الآن** → `POST /api/mlm/settlement` مع `admin_id`.

- **الهدف:** مراجعة طلبات شحن المحفظة.
- **البيانات:** `GET /api/wallets/topups?status=`
- **الفلاتر:** بحث بالاسم/البريد، الحالة (معلق/تم الشحن/مرفوض)، زر بحث.
- **الجدول:** رقم الطلب، الطالب، المبلغ (EGP)، رقم المحوّل عليه، طريقة الدفع، صورة الإثبات، الحالة، الإجراء.
- **الأزرار:**
  - «موافقة» → `PUT /api/wallets/topups/:id/approve` — يضيف الرصيد.
  - «رفض» → `PUT /api/wallets/topups/:id/reject` (بتأكيد).
- **ملاحظة:** الطلبات المعلقة فقط لها أزرار.

### 4.2 ⬆️ طلبات الترقية (`UpgradeRequestsPage`)

- **الهدف:** قبول/رفض طلبات ترقية نوع الحساب.
- **البيانات:** `GET /api/users/upgrade-requests/list`
- **الفلاتر:** بحث، الحالة (معلق/تمت الموافقة/مرفوض).
- **الجدول:** الطالب، الإيميل، الهاتف، تاريخ الطلب، الحالة، الإجراء.
- **الأزرار:**
  - «قبول» → `PUT /api/users/upgrade-requests/:id/approve`.
  - «رفض» → `PUT /api/users/upgrade-requests/:id/reject` (بتأكيد).

### 4.3 🎓 قائمة الطلاب (`StudentListPage`)

- **الهدف:** عرض مبسّط للطلاب في بطاقات.
- **البيانات:** `GET /api/users` ثم تصفية `role = student`.
- **العناصر:** بحث + فلتر رتبة (غير مفعّل فعلياً)، بطاقة لكل طالب (الاسم، البريد، الرتبة، الرصيد، كود الإحالة، عدد المباشرين).
- **ملاحظة:** نسخة قديمة/بديلة؛ صفحة «إدارة المستخدمين» تغني عنها.

### 4.4 💳 بوابات الدفع (`PaymentGatewayPage`)

- **الهدف:** إدارة أرقام/حسابات الدفع التي يحوّل إليها المستخدمون.
- **البيانات:** `GET /api/payment-gateways`
- **3 عدّادات:** الإجمالي، فودافون كاش، انستاباي.
- **بطاقة لكل وسيلة:** النوع، الرقم/الحساب، التسمية، الحالة، التاريخ.
- **الأزرار:**
  - «+ إضافة وسيلة دفع» → نموذج (النوع، الرقم، تسمية).
  - تعطيل/تفعيل → `PUT /api/payment-gateways/:id`.
  - تعديل → `PUT`.
  - حذف → `DELETE` (بتأكيد).
- **ملاحظة:** تظهر للمستخدم في صفحة شحن الرصيد.

### 4.5 🤖 مفاتيح Gemini وGroq (`GeminiKeysPage`)

- **الهدف:** إدارة مفاتيح الذكاء الاصطناعي.
- **البيانات:** `GET /api/settings/gemini-keys` + `GET /api/chat/keys-status`
- **4 عدّادات:** إجمالي المفاتيح، النشطة، المتأخرة (Rate-limited)، المدخلة حالياً.
- **حالة المفاتيح الحية:** كل مفتاح مقنّع + حالته + مدة التهدئة.
- **مفتاح الشات بوت (Groq):**
  - الحالة (مفعّل/غير مفعّل).
  - حقل `gsk_...`.
  - حفظ → `PUT /api/chat/groq-key`.
- **إدخال مفاتيح Gemini:**
  - حقل لكل مفتاح، إضافة/حذف.
  - حفظ → `PUT /api/settings/gemini-keys`.
- **ملاحظة:** المفاتيح تُخزّن في القاعدة وتُحمّل تلقائياً؛ التبديل تلقائي عند تجاوز الحد.

## 6. الأعطال الشائعة وكيفية علاجها

| المشكلة | السبب المحتمل | الحل |
|---|---|---|
| «جاري التنفيذ...» لا تختفي | طلب فشل بدون إغلاق | أعد تحميل الصفحة (F5) |
| الصفحة تعرض «جارٍ التحميل» مع الـ Overlay | نسخة قديمة | حدّث الواجهة (Ctrl+Shift+R) |
| 401 عند كل طلب | الجلسة انتهت أو أُلغيت بجلسة جديدة | سجّل خروجاً ثم دخولاً |
| 403 في إدارة الأدمنز | الحساب `admin` وليس `manager` | استخدم حساب مدير |
| «الرتبة غير موجودة» | الرتبة معطّلة أو الاسم مختلف | فعّل الرتبة من إدارة الرتب |
| العمولة لا تُصرف | المستخدم `commission_exempt = 1` أو لم يحقق الحد الأدنى | راجع الملف الشخصي والإعدادات |
| بيانات قديمة تظهر | كاش 20 ثانية | انتظر 20 ثانية أو نفّذ أي تعديل |
| حفظ مدة العضوية بطيء | إرسال إشعارات لكل المستخدمين | طبيعي (3–5 ثوانٍ) |
| تكرار الإشعارات | حفظ نفس القيمة أكثر من مرة | لا يحدث الآن؛ يُرسل عند التغيير فقط |

2. انسخ محتويات `dist` إلى `hostinger-update/admin`.
3. ارفع مجلد `admin` إلى Hostinger يدوياً (لا يوجد وصول FTP من هنا).
4. افتح الموقع واضغط **Ctrl + Shift + R** لتحديث الكاش.

  `db-backups/turso-2026-10-24T20-53-53/`
